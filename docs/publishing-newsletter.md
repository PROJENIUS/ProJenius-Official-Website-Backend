# News, Blog and Newsletter module

The publishing module uses MongoDB collections `content_articles`, `newsletter_subscribers`, `newsletter_campaigns`, `newsletter_deliveries`, and `publication_events`. Blog and News & Insights share `ContentArticle` with `contentType` set to `blog` or `news`; course announcements reference the existing `courses` collection. Subscriber records are referenced by delivery records and are never returned from public endpoints.

The public `/api/news` feed combines published Blog and News articles, with category, search, and pagination filters. `/api/news/:type/:slug` remains the type-scoped article detail API. Public details use `/news-insights/:type/:slug`; legacy `/blog/:slug` links redirect into that route. New newsletter campaign snapshots use the unified detail URL; existing campaign snapshots are not rewritten. No collection migration is needed because both editorial types already use `content_articles`.

The website footer subscription requires explicit consent and activates the subscriber directly, recording its source and acceptance timestamp before queuing the branded welcome email. Repeated requests for an active subscriber do not send another welcome email. Failed welcome delivery stays queued for the existing retry worker. Previously unsubscribed addresses are reactivated only after a new consented request; unsubscribe timestamps are retained in `unsubscribeHistory`. The legacy confirmation endpoint remains available for pending records and links created before direct subscription was enabled, but new footer submissions do not create confirmation tokens or send confirmation emails.

Article images use the existing `public_uploads/publishing` storage and upload endpoint. New or edited galleries are limited to five images; an existing article with more than five can be reduced without losing media, but cannot have more images added until reduced. Video entries are validated HTTPS YouTube or Vimeo links, stored as provider and video ID metadata, and embedded from fixed provider origins. Video files are not uploaded or stored by this module.

Declared indexes include unique `(contentType, slug)`, unique normalized subscriber email, unique confirmation-token hash, unique campaign idempotency key, unique publication-event idempotency key, unique `(campaignId, subscriberId)`, and query indexes for typed and unified public publication/category feeds, schedules, campaign work, delivery work, and campaign status summaries. The mixed feed indexes are additive; the type-scoped unique slug index is retained to preserve legacy slug relationships and type-aware URLs.

At backend startup, `initializeDatabaseModels()` creates missing collections and calls each model's declared `createIndexes()` against the configured `ProJeniusBackend` database. This procedure does not drop collections or indexes. Before first production startup, back up the database and inspect any index creation errors in the deployment logs; unique-index creation can fail if duplicate historical data already violates the constraint. Do not use the old `test` database or run destructive cleanup to resolve such an error.

`PUBLIC_SITE_ORIGIN` is used for public article/course links and confirmation/unsubscribe pages. `PUBLIC_API_ORIGIN` may be set to the public API origin for hosted images and one-click unsubscribe. Both values are validated as absolute HTTP(S) origins (HTTP is accepted only for localhost during development). Email provider settings continue to use the existing shared email service. This module introduces no provider credentials.

Campaign events and recipient deliveries are stored before send. Workers use database leases, a unique campaign/recipient key, recipient eligibility rechecks, and bounded retries. Provider submission can time out after acceptance; delivery therefore has at-least-once semantics and may duplicate a message in that uncertain case. `sent` means the provider accepted the message, not that it reached an inbox. New mail is never sent by automated tests; test transport overrides and a loopback-only MongoDB memory server are used.
